# Phase 3: 포맷 확장 — PPTX · HWP (각각 독립 측정 게이트)

## 목표
PPT·한글을 편입한다. 단 **렌더러를 미리 확정하지 않는다** — 코퍼스 실측 후 {클라 JS 렌더 | 딥링크 폴백}을 데이터로 결정한다.
"저화질 허용"은 고화질이 어려울 때의 폴백 허가이지 "깨져도 됨"이 아니다(RISK-B). kill switch: "한컴/파워포인트보다 나쁘지 않을 것".
신규 파서 = 신뢰 불가 입력 → 보안 하드게이트 6종을 **파서별 재증명**한다(zipGuard 자동 적용 가정 금지, CJK 폰트 깨짐 검사 추가).

## P3a — PPTX
```
✓ 실 .pptx 코퍼스 10~20개 확보 + 3단 채점표(정상/읽기가능/깨짐)
✓ pptxjs류 클라 JS 렌더러 실측(품질·jQuery 의존·번들 영향)
✓ 미달 시 폰 폴백 = "다른 앱으로 열기" 딥링크(깨진 렌더 출하 금지)
✓ 구형 .ppt(바이너리)는 스코프아웃 유력 — 측정으로 확정
```
**체크리스트:**
- [ ] PPTX 코퍼스 + 채점
- [ ] 클라 렌더러 실측 → 편입/폴백 결정
- [ ] (편입 시) zip bomb/XXE/XSS/파일명/CJK폰트 하드게이트 재증명 테스트

## P3b — HWP
```
✓ 실 .hwp/.hwpx 코퍼스 확보. .hwp:.hwpx 실비율 먼저 측정(RISK-C)
✓ 비율에 따라 우선순위: 바이너리 .hwp(hwp.js) vs .hwpx(OWPML) vs 폴백
✓ (선택) LibreOffice 로컬 변환은 데스크톱 전용 — 폰 HWP는 딥링크 폴백이 현실적 결론일 수 있음
```
**체크리스트:**
- [ ] HWP 코퍼스 + .hwp:.hwpx 비율 측정
- [ ] 렌더 경로 결정(클라 파서/변환/폴백)
- [ ] (편입 시) 보안 하드게이트 재증명 + CJK 폰트 검사

## 완료 정의(DoD)
- 포맷별 "읽기 ≥임계 AND 한컴/파워포인트보다 나쁘지 않음" → 편입. 미달 → **딥링크 폴백 확정**.
- 편입 포맷은 보안 6종 하드게이트 파서별 재증명 + CJK 폰트 깨짐 없음.
