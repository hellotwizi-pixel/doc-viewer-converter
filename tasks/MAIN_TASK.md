# 메인 Task: doc-viewer — 편집 불가 문서 뷰어 (4포맷 · 폰·PC)

## 프로젝트 개요
- **목표**: 카톡/메일로 받은 PDF·PPT·워드(DOCX)·한글(HWP)을 편집 없이 "바로" 열람하는 순수 뷰어. 폰·PC 둘 다.
- **품질 정책**: 고화질 우선, 어려우면 "읽는 데 무리 없는" 저화질 허용(단 "한컴/파워포인트보다 나쁘지 않을 것" = kill switch). 미달 포맷은 렌더 대신 딥링크 폴백.
- **아키텍처**: 렌더 코드베이스 1개(웹뷰어) + 전달 셸 — 설치형 PWA(PC·폰 브라우저) + 안드로이드 WebView 래퍼. 백엔드 0, egress-0(문서 외부 유출 0), 순수 클라이언트.
- **스택**: Vite + TypeScript + Service Worker(PWA), UI 바닐라 TS. 배포: Vercel CLI 정적.
- **상태**: ✅ 재설계 조건부 승인 (CTO: tech-critic-lead, 신뢰도 82). iOS 자동 바로열기 미지원(RISK-A, 문서화).

---

## 전체 구조 (가치 × 확실성 ÷ 비용 순서)
```
P1 — MVP + 실코퍼스 게이트 닫기        [크리티컬 패스 · PDF+DOCX 실검증]
     PDF(pdf.js 고화질) + DOCX(mammoth 읽기수준) 순수 클라 PWA. (구현 완료)
     남은 것: real 코퍼스 ≥15개로 충실도 DoD 확정(현재 UNVERIFIED, realCount=0).

P2 — PC "바로 열기" (file_handlers)     [최저비용 · 최고확실성 · 순수 웹]
     이미 되는 PDF+DOCX에 데스크톱 PWA file_handlers → 파일 더블클릭=뷰어 오픈.
     네이티브 0 · 서명 0 · 보안 신규표면 0.

P3 — 포맷 확장 (각각 독립 측정 게이트)   [불확실 · 렌더러 선확정 금지]
     P3a PPTX: 코퍼스 실측 → {클라 JS 렌더 | 딥링크 폴백} 데이터로 결정.
     P3b HWP : .hwp:.hwpx 실비율 먼저 측정 → {클라 파서 | 딥링크 폴백}.
     신규 파서마다 보안 6종 하드게이트 재증명 + CJK 폰트 깨짐 검사.

P4 — Android WebView 래퍼 + intent-filter [최고비용 · 다게이트 · 조건부]
     카톡 "다른 앱으로 열기"에 노출. 착수 게이트: 축1 정당화 AND 해당 포맷 P3 통과
     (딥링크 폴백 포맷은 intent 등록 금지 — 안 열리는데 뜨면 UX 배신).

iOS — phase 없음. "공유 → 뷰어" 수동 한 단계로 한정(RISK-A).
```

| Phase | 이름 | 종속 | 상태 | 산출물 |
|-------|------|------|------|--------|
| P1 | MVP PDF+DOCX + 실코퍼스 | 실코퍼스(UI-3) | ✅ 구현·검증 (충실도 DoD UNVERIFIED) | PWA + 축1 데이터 |
| P2 | PC 바로열기(file_handlers) | 없음(순수 웹) | ✅ 구현 (실동작 검증=UI-6) | 데스크톱 바로열기 |
| P3 | 포맷 확장(PPTX·HWP) | 코퍼스 실측 | ✅ 읽기수준 렌더 구현·검증 (충실도 GO=UI-3) | 자체 파서 + 폴백 |
| P4 | Android WebView 래퍼 | 축1 + P3 통과 | ✅ 소스 완비 (빌드·기기=UI-4) | `android/` 프로젝트 |

## Go/No-Go 기준 (요약, 상세는 각 phase 파일)
- **P1**: PDF 정상 100% / DOCX 읽기 ≥90% (real 코퍼스 ≥15, 미달 시 UNVERIFIED). 보안 6종 PASS. 축1 개발자측 계측 완료.
- **P2**: 데스크톱 설치형 PWA에서 파일 더블클릭 → 뷰어 오픈 실동작.
- **P3**: 포맷별 "읽기 ≥임계 AND 한컴/PPT보다 나쁘지 않음" → 편입, 미달 → 딥링크 폴백. 파서별 보안 재증명.
- **P4**: 실기기 카톡 "열기" 목록 노출 + 3탭 이내 열람 100%(10회). (실기기=user-intervention)
